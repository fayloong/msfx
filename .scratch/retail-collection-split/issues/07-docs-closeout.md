### CLAUDE.md 对账结果

逐项核对了票面点名的七块。**零售采集 / 补传 / 三个数据页 / 常用命令 / source 取值 / SQLite 表说明与代码一致**；查出并改掉的是**与本票主题无关的既有文档漂移**（都是文档过时，不是代码缺陷）：

1. **文件树漏项**：`public/assets/`（8 个已入 git 的前端资源文件，文档里写着"前端 CDN"——实际是本地自托管）、`tests/company.txt`（gitignore 的凭据草稿）、`tests/singlerelation_*.json`、根目录的 `docs/` / `.scratch/` / `CONTEXT.md` / `composer.json` / `.gitignore`
2. **`upload_tasks.source` 取值写错**：文档列了 `batch_check` / `batch_retry`，实际现行代码只写 `cron` / `manual` / `retail`（`batch_check` 只在 2026-07-29~30 的 40 行旧数据里，`batch_retry` 在任务表里一条都没有——这两个是 `upload_logs` 的取值）。任务页来源下拉那句"只列任务表会出现的五个值"与之同源，一并改准
3. **`last_checked_at` "两脚本一致"不成立**：`check_bill_status` 在"已确认在平台"分支会标记任务已处理并 touch；`check_failed_logs` 的同名分支一个字都不写（历史记录不动），因此**不** touch——与同节上一段自己写的口径本来就矛盾
4. **引号里的打印原文不存在**：`RetailBatchUpload` 条目引的"跳过未识别 N 条"，脚本实际打的是"跳过非门店企业（含未识别）N 条"（票 06 收口时改的文案，文档没跟上）
5. **`upload_pending.php` 当前没在跑**：它的三条 crontab 条目**全部被注释**（"暂不启用"），而 CLAUDE.md 全篇把它当定时在跑（cron 表不列它、文件树与"定时上传"节照旧）。已在文件树、该节开头、cron 表注、常用命令四处写明——这是**当下运维状态**，不写清楚下一个人会以为批发自动上传是活的
6. **两个遗留列没进字段表**：`upload_tasks.status` 与 `upload_logs.success`（2026-07-29 拆分时本应删除，本机 SQLite 3.7.17 不支持 `DROP COLUMN`，那一步只打印 SKIP——列与旧数据都还在，且是**旧词表**）。两张表各补一行"遗留列，勿读勿写"
7. **小项**：`uploaded.php` 的"（upload_logs success=1）"已过时（判据早收进 `App\RecordQuery`）；`backfill_update_state.php` 的判据漏了 `source IN ('retail_retry','manual')` 这一层；环境配置的 nginx 监听写法补上访问白名单

### 专项 grep 复核（验收第 5 条）

**两侧都 grep 了**（旧词 `过滤` / `NOT EXISTS` / `隐藏` / `挡在门外` / `不可见`，以及新词说旧意思的句子）。结论：旧口径表述基本只剩两类——① 已就地加修订注的**历史记录**（ADR 0007 修订注一/二/三、ADR 0013/0016 的 Context、`retail-chain/issues/03` 那一节，均已标明时间边界或已在本轮补上结案注）；② **与"已上传"无关**的"过滤/隐藏/不可见"（拆分空码、非药品行过滤、页面对零售行隐藏某一格、失败页的 `NOT EXISTS` 判重、快照欠账"在本系统里不可见"）。`config/sql.php` 的调试残留段属第 ① 类——它已写明"ADR 0007 曾判为去掉 → 测试阶段临时加回 → **2026-10-02 票 02 改成分流**，以脚本为准"。

**会被误读的活文档共三处，本轮都补了结案注**（不改历史原文，只加一句"现口径是什么"）：`retail-chain/spec.md` 两处测试阶段的就地注记、`retail-chain/issues/03` 那节"测试阶段口径变更"。
