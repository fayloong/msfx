# 03: 零售单据采集入库，上传任务页看得见

- Type: task
- Status: ready-for-agent
- Blocked by: 02
- 关联：spec.md §5/§6、docs/adr/0007-retail-no-platform-reconciliation.md、docs/adr/0008-retail-claim-by-platform-id.md、`.scratch/retail-chain/probe-findings-2026-09-29.md`

## 要交付的行为

运维跑一次采集（或 cron 到点），指定日期的门店单据出现在"上传任务"页上，**每条都带着归属的门店名**；
归属不到的显示"未识别"且一眼看得出来；这些记录不会被任何自动上传链路取走。

## 范围

**新脚本 `scripts/fetch_bills_retail.php`**（命名与位置对齐 `fetch_bills.php`）

- 用 `App\SqlSrvHelper` 现有连接**直接查 4 段式链接服务器名** `dyt.msfx.dbo.zsm_ls` / `zsm_ls_code`（实测可用，全表 `COUNT(*)` 638ms），不需要新连接封装
- 两步 SQL，先头后码：
  - **头**：必须先按 `bill_code` 去重——`321` 存在 14 列值全同的完全重复行（同一单号最多 120 行、无任何区分列），不去重会让下一步按单号取码时追溯码被放大最多 120 倍
  - `bill_time` 是 `varchar(10)` 的 `YYYY-MM-DD`（不是 datetime），字符串范围比较即日期比较
  - 单据类型写死 `104`/`203`/`321`/`116` 四种（`999` 语义未明，用户判定不采）
  - **码**：按单号批量取，`group by bill_code, trace_codes` + `order by` 保证拼接结果确定（一码一行，表里没有排序列且 `bs` 恒为 1）
- 参考 SQL 在 `config/sql.php` 的 `$get_up_task_retail` 是调试残留，**别照抄**（写死单一 `bill_type='203'`、无日期范围、无去重）
- 脚本失败（源库不可用）非零退出且**不写库**

**门店认领**：走 `App\Enterprise::claim()`（工单 01 已实现并有测试覆盖），不要在本票里另写一套匹配

- 按单据类型取 ID 列命中该门店登记过的任一平台 ID（`321`/`116` → `from_user_id`，`104`/`203` → `to_user_id`）
- ID 为空或未命中 → 回退 `oper_ic_name` 与配置门店名精确相等
- 都不命中 → `company='未识别'`，**照常入库**（丢单比错标更危险，必须能看见"有单没被认领"）
- `claim()` 返回 `name_unmatched` 时记一条 JSONL 警告，**不改判定**（ID 认到了、源库名字却对不上任何门店 → 疑似错名/改名/已关店）

**落库**

- `task_status='待补传'`（**不复用 `等待上传`**，语义是"cron 会来取走并上传"）、`source='retail'`、`company` 取认领结果、`credential` 取该企业 primary 凭据键（待配凭据时为 null）
- `ent_name`（往来单位）零售没有这个概念，留空
- 幂等：按 `(company, djbh)` 去重，重复跑不产生新行
- **不设计数门卫**：`data/fetch_bill_counter.json` 那套是为"重视图查询空转"设计的；零售是一次 ~0.6s 的全表扫 + 去重保证幂等，门卫只省 0.6s 却多一份要维护的状态文件
- **不需要拆单**：实测单张单据码数上限 1,718 < 3,500

**页面**

- 上传任务页表格加"所属企业"列；`未识别` 的行显著标记
- **零售行的重传按钮关闭**（隐藏或禁用）：零售补传入口在工单 06 才落地，在此之前点它只会撞上工单 02 设的守卫并报错

**调度**

- 零售采集不调平台 API，无 8-20 点限流约束；加 cron 条目与 `fetch_bills.php` 同频，并在 `CLAUDE.md` 的 cron 时间表补一行（文档随本票同一次提交）

## 验收

- [ ] 指定日期跑一次采集，入库单据数 == `zsm_ls` 按类型 + 日期范围的**去重单号数**（不是行数）；紧接着再跑一次，新增 0 条
- [ ] 抽样核对认领：`321`/`116` 的单据按 `from_user_id` 认到正确门店（源库这些行没有门店名，只能靠 ID）；`104`/`203` 按 `to_user_id`
- [ ] 造一条认领不到的记录：页面上"未识别"显著可见，且它照常入库、没有被丢弃
- [ ] 上传任务页既有筛选（单号 / 往来单位 / 状态 / 单据日期 / 任务创建时间）行为不变
- [ ] 源库不可用时脚本非零退出，且库里没有任何新增行
